Shape B · 2–3 lines, why in parentheses

The guards

Each guard denies one class of command:

  • no-rm-tree: a recursive rm or find -delete, unless the target is a generated directory or a place the agent owns (an agent once took a directory of the user's captures with rm -rf examples).
  • no-git-footguns: git add -A, commit -a, stash pop, force-push, reset --hard and the other moves that throw work away, often in a checkout another session shares.
  • no-delete-stacked-base: deleting a remote branch that an open PR is based on (GitHub silently closes the PR).
  • issue-door: a second GitHub issue create, transfer or delete in the same human turn, or any inside a loop (an agent once filed a batch of duplicate issues on a plan approved once).shortened
  • public-issue-guard: posting a term from your private list to a public GitHub repo (once up, it is in every mirror). Off until you name the list; see Configuration.new
  • no-checkout-home (opt-in, off by default): a git or yadm checkout or switch of the branch in your home directory, when $HOME is itself a worktree (every shell on the machine follows it).shortened
  • no-foreign-worktree (opt-in, off by default): a command or edit that reaches into another session's git worktree (read its branch with git show <branch>:<path> instead).new
  • ask-first: a command the repo lists as costly, until you approve that one run (an agent once ran a 46-minute, all-core test sweep to check a small change, then started it again). See Ask first.
  • prose-budget-commit: a git commit whose staged prose runs over the repo's own word budgets, as counted by prose-budget, where installed.

Five bullets are exactly as on main today. Tags are for this preview only.
